# Project Instructions

Versioned home for user-scope coding-agent configuration. After `install.ps1`, `hooks/` is visible at `~/.claude/hooks/` (and vice-versa) via a Windows junction. This repo's own `global-CLAUDE.md` supplies the global instructions and applies here in full; below is only what's repo-specific.

## Repo-specific conventions

- **Hooks are user-scope, fleet-wide.** Never tune a hook to one project's quirk — put the quirk in `hooks/projects.toml` (project keys detected by `cwd` prefix) and keep the hook code generic.
- **Hooks are wired into `~/.claude/settings.json` via the shared `run-hook.ps1` shim**, which dispatches to the named Python module through this repo's own project `.venv`, falling back to a system Python if the venv is ever absent (fleet-config#350). The shim path uses **forward slashes** — `C:/Users/rober/.claude/hooks/run-hook.ps1`. Never write backslashes into a `settings.json` command string. **Named exception:** the template's `Bash`/`PowerShell` `PreToolUse` entries call the venv Python straight at `hook_dispatch.py` (fleet-config#1287), skipping the shim and its venv-missing fallback on purpose — one Python process answering for every hook on that matcher beats a `run-hook.ps1` start per hook (fleet-config#1274). Accepted trade-off: if `.venv` is ever absent, the secret-scan, no-AI-trailer, safe-kill and venv-discipline guards on those two matchers fail open together, with no system-Python fallback.
- **Always the absolute Windows PowerShell 5.1 path** in `settings.json` commands: `C:/Windows/System32/WindowsPowerShell/v1.0/powershell.exe`.
- **Hooks refuse through `_lib.block()`** (Claude: exit 2 + stderr; confirmed Codex `PreToolUse`: structured deny + exit 0; Pi: versioned decision consumed by `policy_hooks.ts`); non-blocking hooks exit 0 with a single short nudge. Never hand-roll either — `_lib.block()` and `_lib.warn()` own the wire format, which is per-event and per-harness: plain exit-0 stdout only reaches the model on `SessionStart`/`UserPromptSubmit`/`UserPromptExpansion`. Claude `PreToolUse` uses `systemMessage`; Codex `PreToolUse` and `PostToolUse` use `hookSpecificOutput.additionalContext`; other Claude `PostToolUse`-class events use the event's supported additional-context field (fleet-config#681, #745). A nudge printed to a channel the model never reads is a guard that only reports — worse than no guard.
- **Hooks read stdin as JSON** via `_lib.read_stdin_json()`; PowerShell shims read stdin as UTF-8 and pipe it on UTF-8-encoded straight to the Python module (`run-hook.ps1`; fleet-config#912).
- **Foreign-harness payloads are translated in exactly one place** — `_lib.normalize_payload()`, called from `read_stdin_json()` (fleet-config#491). A hook must never learn a second harness's key names, event vocabulary, or tool ids; a harness sending something new means extending the maps there. Claude-shaped payloads are returned as the *same object*, asserted by `tests/payload_normalization/test_payload_normalization.py`, because `hooks/` is junctioned live into `~/.claude/hooks` — a merge is fleet-wide against running sessions the moment it lands. Likewise `_lib.block()` owns the per-harness refusal dialect listed above, plus Grok — which additionally needs a `deny` decision on stdout, because it reports our 2 as 1 and fails **open** on anything else. Verify a real refusal live in the target harness. Procedure: `docs/adding-a-coding-harness.md`.
- **Every `subprocess` spawn passes `creationflags=NO_WINDOW`** — `_lib.NO_WINDOW` in `hooks/`, `from no_window import NO_WINDOW` in `skills/_lib/` and `.claude/skills/*` (fleet-config#412). Never re-inline the `sys.platform == "win32"` ternary; this repo's scheduled skills are the convention's console-less parent. Repo-root modules import it from `skills/_lib/no_window.py`. `tests/run_acceptance.py` parses `hooks/`, `skills/`, `.claude/skills/` and the repo-root `*.py`, and fails on any spawn missing the flag or any `NO_WINDOW` defined outside those two homes (fleet-config#930); `tests/` itself is exempt.
- **Every `git` call goes through `run_git`** — `_lib.run_git` in `hooks/`, `git_run.run_git` (text) / `git_run.run_git_bytes` (byte-exact reads) in `skills/_lib/` and `.claude/skills/*` (fleet-config#677). Never hand-roll `subprocess.run(["git", …])`: the wrapper is where `git_env()`'s `GIT_OPTIONAL_LOCKS=0` lives — the fix for the stranded 0-byte `index.lock` (fleet-config#667) — and a raw spawn opts back out invisibly, still exiting 0 with the right answer. `tests/run_acceptance.py`'s `git_wrapper` check scans the three runtime trees and fails on any literal `git` argv outside the two wrapper files themselves.
- **Nine ratchets gate the acceptance run.** Each `tests/acceptance/…_gate.py` below runs a vendored `scripts/<ratchet>.py` — byte-for-byte from project-scaffolding; re-vendor with `/propagate-vendored <ratchet>`, never edit. Shared rules: existing debt is baselined in `.<name>-ratchet-baseline.json`, not hidden; burn the baseline down with `--update-baseline`; only `--allow-additions` adds, and shows in review. Fix the finding (reword, delete, split) rather than raise the baseline. Exit 3 means the detector could not run, count, measure, scan or resolve — NOT CONFIRMED, a failure, never a skip — so each is a dedicated check, never a `standalone_dispatch` row (`shared.SKIP_EXIT` is also 3). Config is the `.fleet.toml` table named after the script (`[static_ratchet]`, `[docs_ratchet]`, …).
  - **Static analysis** — `tests/acceptance/static_ratchet_gate.py` / `scripts/static_ratchet.py`, `.static-ratchet-baseline.json`: a duplicate block (jscpd), unused import/variable (ruff `F401,F841`), or ruff bug (`B`) or security (`S`) finding (`S113` strict).
  - **Docs** — `tests/acceptance/docs_ratchet_gate.py` / `scripts/docs_ratchet.py`, `.docs-ratchet-baseline.json`: `README.md` passes 40 KiB or its baselined size, or `README.md` or `docs/**/*.md` gains an issue reference, a dated heading or a changelog heading. Docs state the present-tense why; history belongs to git, PRs and issues. No `exclude` is set because `docs/` holds no generated or dated report folders.
  - **Structure** — `tests/acceptance/structure_ratchet_gate.py` / `scripts/structure_ratchet.py`, `.structure-ratchet-baseline.json`: a file passes 1,000 lines, a function 100 lines or a flat directory 40 modules and is new or above its baseline entry, or the root folders do not match `shape = "skills-governance"` plus `extra_roots`. The baseline is empty and stays recorded at real size, never excluded: nothing may grow past a limit, so a new module goes in a subject subfolder (`tests/<subject>/`, a `skills/_lib/<domain>/` package), not a flat directory, and a suite past 1,000 lines splits into a `_suite.py` plus ordered parts. A new root folder is declared in `extra_roots`, not allowed by default.
  - **Comment** — `tests/acceptance/comment_ratchet_gate.py` / `scripts/comment_ratchet.py`, `.comment-ratchet-baseline.json`: a file's count of `#NNN` issue references inside *comments* (Python, JS, CSS, PowerShell; docstrings and strings are not scanned) rises above its entry, or a file not in the baseline carries any. A comment states the present-tense why; the history lives in the issue and `git log`.
  - **Instruction** — `tests/acceptance/instruction_ratchet_gate.py` / `scripts/instruction_ratchet.py`, `.instruction-ratchet-baseline.json`: a prompt-audit lint rule's hit count in an instruction file (`CLAUDE.md`, `global-CLAUDE.md`, every `SKILL.md` under `skills/` and `.claude/skills/`, the docs a skill links to) rises above its entry, or a file passes its size cap — a finding the weekly `/prompt-audit` would file fails at ship time instead.
  - **Doc references** — `tests/acceptance/doc_refs_ratchet_gate.py` / `scripts/doc_refs_ratchet.py`, `.doc-refs-ratchet-baseline.json`: `README.md`, `CLAUDE.md` or `docs/**/*.md` names a repo path, `python -m` module or relative link that does not exist. Point the reference at what exists now; a pointer into another repo's tree goes in `allow_refs`, not the baseline.
  - **Dead code** — `tests/acceptance/dead_code_ratchet_gate.py` / `scripts/dead_code_ratchet.py`, `.dead-code-ratchet-baseline.json`: a function, class or method that nothing in the tracked tree refers to. Delete the definition or call it; a real entry point the rules miss (a framework hook called by name) goes in `entry_decorators` or `allow`, not the baseline. Every vendored file must be declared in `.fleet.toml` `[vendored]` first, or its unused API is reported as this repo's.
  - **Conventions** — `tests/acceptance/conventions_ratchet_gate.py` / `scripts/conventions_ratchet.py`, `.conventions-ratchet-baseline.json`: a file's hit count for an enabled `ast` rule rises above its entry: `no-window` (a spawn without `creationflags=`), `logging-not-print` (a `print` in `skills/_lib/`; hooks print the wire format by design), `no-drive-path` (a drive-letter literal) and `git-wrapper` (a raw `git` spawn outside `hooks/_lib.py` and `skills/_lib/git_run.py`). `secret-compare` stays off: the repo has no constant-time compare helper. `tests/**` is `exclude`d: tests are exempt from `no-window` and every other rule skips test modules. A legitimate single exception carries `# <rule>-exempt: <reason>` (the KEY=value protocol prints in `skills/_lib/worktree/worktree_config.py`, the machine-default fleet paths). The local `spawn_scanner` checks stay: they also require the value to be `NO_WINDOW`, scan `gh`, and walk the root modules.
  - **Runtime write** — `tests/acceptance/runtime_write/runtime_write_ratchet_gate.py` / `scripts/runtime_write_ratchet.py` with its sibling `scripts/runtime_write_resolve.py` (re-vendor both: `/propagate-vendored runtime_write_ratchet,runtime_write_resolve`), `.runtime-write-ratchet-baseline.json`: a tracked Python file gains a write target (open for writing, `Path.write_*`, `mkdir`, a log `FileHandler`, `sqlite3.connect`, a copy destination) resolving under `hooks/`, `skills/`, `scripts/` or `.claude/`, or a new one it cannot resolve. The same stage brackets the whole acceptance run: `--snapshot` before the first check, `--probe` after the last, failing on any untracked or ignored file the run left under a code folder. Runtime output belongs in the state dir or a temp dir, never beside the code.
- **Scheduled-skill launchers live *with* the skill:** `.claude/skills/<skill>/run-weekly.bat`, never at the repo root. Body is exactly `cd /d <working-dir>` then this repo's `.venv` Python invoking `skills/_lib/claude_progress.py "/<skill>" [flags] --permission-mode bypassPermissions` — the adapter owns `claude -p --output-format stream-json --verbose`, emits flushed human-readable milestones, and preserves Claude's exit code. Working dir is the skill's repo (`cd /d E:\automation\fleet-config`), or `E:\automation` for genuinely fleet-wide skills (`/audit-fleet`); `bypassPermissions` is required because a scheduled run has no human to answer prompts; add `--model`/`--effort` only when needed. Sister repos follow the same shape in their own tree (e.g. life-os `.claude/skills/_recap/run-weekly.bat`). The app-launcher Job's `script_path` points at this file; live `jobs.json` is machine-local, `jobs.sample.json` carries the committed example. `claude_progress.py` is the compatible facade over `scheduled_runner.py`; new explicitly authorized Codex callers use the supported flags in [docs/scheduled-runners.md](docs/scheduled-runners.md). Do not switch existing schedules as a side effect of adapter work.

## Adding a new fleet project

New repo under `E:/automation/` → **always** add a minimal entry before the `[global]` block of both the tracked `hooks/projects.toml.example` and the machine-local, gitignored `hooks/projects.toml`, regenerate the maps and place it on the architecture map, all in the same PR — `tests/run_acceptance.py`'s `fleet_membership` check fails the gate by name otherwise (fleet-config#640). Entry shape, the three regeneration commands, the `ARCHITECTURE.md` row, the residual `_adopted` registry and `architecture_ignore`: [docs/adding-a-fleet-project.md](docs/adding-a-fleet-project.md).

## Verification

```powershell
# 1. Byte-compile every hook and shared skill helper (recursive — PowerShell does
#    not glob-expand arguments to a native exe, so `py_compile hooks/*.py` fails)
& E:/automation/fleet-config/.venv/Scripts/python.exe -m compileall -q hooks skills/_lib

# 2. Run the acceptance matrix (sample stdin payloads per hook + the helper unit tests)
& E:/automation/fleet-config/.venv/Scripts/python.exe tests/run_acceptance.py
```

Invoke this repo's `.venv` interpreter by its absolute path (as above) — a bare `py`/`python` is not reliably on `PATH` here, so it silently fails wherever a skill or doc uses it (fleet-config#256). Create the venv once with `py -m venv .venv` (or any Python ≥3.12), then `pip install -r requirements.txt` for `ruff`; the runtime is stdlib-only, ruff is a dev tool, and the acceptance run's ratchet stage also needs Node (`npx`). Don't claim a hook works without driving it through `tests/run_acceptance.py`.
