# Hooks

The Tier 1 hook reference: what each hook does, what it blocks, and why it
exists. `hooks/` is junctioned into `~/.claude/hooks` and `~/.codex/hooks`, so
every entry here is live in every agent that reads those homes the moment it
merges. Per-project nuance (ports, gate triggers, never-kill ports) lives in
`hooks/projects.toml`, never in hook code.

18 hooks under `hooks/` that enforce the rituals I kept correcting Claude on, across the home-stack fleet:

| Hook | Event | What it does |
|---|---|---|
| `pre_commit_no_ai_trailer.py` | `PreToolUse` on `Bash` | Blocks `git commit` messages that include `Co-Authored-By: Claude`, `Generated with Claude Code`, etc. |
| `secret_scan_guard.py` | `PreToolUse` on `Bash` | Blocks `git commit` when a live credential is staged — scans `git diff --cached` and the command string against `_lib.SECRET_PATTERNS`, the single definition of "what a credential looks like" for this tier, shared with `context_filter`'s redactor (fleet-config#561): Slack tokens (`xox[baprs]-`), `sk-` API keys, GitHub tokens (`gh[pousr]_`), and AWS access key ids (`AKIA…`). Every pattern is live-shaped and `\b`-anchored, so placeholder forms (`xoxb-…`, `xoxb-<token>`) and prose lookalikes (`risk-…`, `highp_…`) are deliberately allowed and never trip it. Extending coverage is a one-line change in `_lib.py`. |
| `gh_body_file_guard.py` | `PreToolUse` on `Bash` | Non-blocking nudge: an inline `gh issue/pr create\|comment\|edit --body` carrying a heredoc/backtick (Bash mangles it) → use `--body-file <tmp>`; a PowerShell here-string (`@'…'@`) run through the Bash tool → wrong shell. `--body-file`/`-F` and plain `gh` reads pass silently. |
| `bash_cmdexe_syntax_guard.py` | `PreToolUse` on `Bash` | Blocks native `cmd.exe /c` because Git Bash/MSYS rewrites `/c` to `C:/` and opens an interactive prompt instead of running the command; use the PowerShell tool or `cmd.exe //c`. Other cmd-only syntax remains a non-blocking nudge: `%VAR%`, builtin+flag (`dir /s`, `del /f`, `copy /y`), and caret (`^`) continuation. |
| `bash_windows_path_guard.py` | `PreToolUse` on `Bash` | Blocks an unquoted Windows drive-letter backslash path (`E:\automation`) in a Bash command — Git Bash strips the backslashes in unquoted word-splitting context, silently mangling the path. A quote/heredoc-aware scan allows a forward-slash path, a single- or double-quoted backslash path, and a backslash path inside a heredoc body (so `git commit -m "$(cat <<'EOF' ... EOF)"` never false-positives); the same command through `PowerShell` is untouched (guard is Bash-only). |
| `safe_kill_guard.py` | `PreToolUse` on `Bash` / `PowerShell` | Blocks blanket `Stop-Process -Name python(w)?` (would nuke sister hubs), `git push --force` to main, `--no-verify`. Port-scoped kills against the project's own webapp port pass through. The force-push rule reads the *refspec being pushed* (or the checked-out branch when the push names none), so a feature branch whose name merely contains `main`/`master` is not blocked. |
| `venv_discipline.py` | `PreToolUse` on `Bash` / `PowerShell` | Blocks `python -m venv venv` (the user's canonical name is `.venv`), `.\.venv\Scripts\activate`, bare `python`/`pip` when a project `.venv` exists. |
| `py_syntax_check.py` | `PostToolUse` on `Edit` / `Write` for `*.py` | Runs `py_compile` against the project's `.venv` and surfaces syntax errors inline. ~50 ms per edit. |
| `docs_dated_filename_guard.py` | `PreToolUse` on `Write` | Blocks a `Write` of a `YYYY-MM-DD-`prefixed file under a `docs/` directory — `docs/` is durable reference, not dated retrospectives (the issue + PR + `git log` are the changelog). Override with `CLAUDE_HOOKS_ALLOW_DATED_DOCS=1`. |
| `block_askuserquestion_chief.py` | `PreToolUse` on `AskUserQuestion` | Blocks `AskUserQuestion` outright when the calling session is chief-managed (same `hooks/state/chief-managed.json` marker `notify_on_idle.py` reads) — the tool renders only in the worker's own PTY, so chief can never see the question or attribute an answer to it. No-ops for an ordinary interactive session, a non-`AskUserQuestion` tool, a missing `session_id`, or a missing/corrupt state file (fails open rather than stranding a worker). Instructs the model to state the question and options as plain output text instead and wait for chief to relay a decision via `chief_ops.py say`. |
| `branch_before_edit_guard.py` | `PreToolUse` on `Edit` / `Write` / `MultiEdit` | Blocks a launcher-dispatched session (`APP_LAUNCHER_SESSION_ID` set, same signal `session_state.py` reads) from editing while the **target file's own directory** resolves to its repo's default branch (`main`/`master`, via `skills/_lib/git_run.resolve_default_branch_ref`) — resolved from the file being written, not the session's cwd, so a worktree worker on its own feature branch and a write to a path outside any repo both pass through untouched. **Gitignored targets are exempt** — a write git will never commit can't break the rule this enforces — so runtime-state files like `life-os`'s `.active-skill` or this repo's `hooks/state/` stay writable on the default branch; the exemption is ignored-paths-only, so an untracked-but-committable new file still blocks. Paths are junction-resolved first, since `~/.claude/hooks/` reaches this repo through one. Fails open on any git ambiguity (non-repo target, detached HEAD, git error); an unresolvable ignore probe fails *closed*. A bare interactive session is never touched — and that env check runs **first**, ahead of any git call, so an ordinary session pays zero process spawns on the fleet's highest-frequency hook path (fleet-config#680). Override with `CLAUDE_HOOKS_ALLOW_MAIN_EDIT=1`. (fleet-config#464; take 2 after PR #472/#477 — the first version resolved from session cwd and was reverted for exactly those two false positives; gitignore exemption fleet-config#489.) |
| `hub_bypass_warn.py` | `PostToolUse` on `Edit` / `Write` for `*.py` | Non-blocking nudge when a `*.py` outside the LLM-hub repo spawns an inline `claude -p` subprocess → route through the local hub at `127.0.0.1:8000` via the standard SDKs instead. |
| `browser_stealth_lint.py` | `PostToolUse` on `Edit` / `Write` | Non-blocking nudge when a browser-launch file (`chrome_launch.py` / `browser.py` / `*_session.py`) launches Chrome but is missing a stealth marker (`--enable-automation` strip, `navigator.webdriver` init, `channel="chrome"`, `AutomationControlled`) → import the project's single-source launch helper. |
| `chief_handover_sessionstart.py` | `SessionStart` | Hands the standing fleet chief its last-written run log back on every session start — fresh boot, resume, or continuing after an automatic compaction (fleet-config#442). The transport half of "compact and continue": chief owns *what* to record (dense, decision-focused prose, written with the `Write` tool at its own checkpoints); this hook only hands it back so chief never has to remember to go read it. cwd-gated to `fleet-config` sessions only; silent no-op with no log yet written. |
| `context_filter_hook.py` | `PreToolUse` on `Bash` / `PowerShell` | Token-reduction hook. Machine-wide switch is `~/.fleet-context-filter/mode.json` (`off` \| `shadow` \| `rewrite`, written by the app-launcher toggle); the `FLEET_CONTEXT_FILTER_MODE` env var overrides per process and is the kill-switch (#541). `shadow`: each supported command runs through the local wrapper, the agent still gets **raw** output, would-save metrics logged. `rewrite` returns compressed output with a local raw-output retrieval key. Both modes log telemetry rows (`ts`, `mode`, `agent`, `session_id`, `cwd` + the token metrics) to `~/.fleet-context-filter/shadow.jsonl`. Active on Claude Code, **Pi** (`pi/extensions/context_filter.ts` → the `compress` subcommand, #545), **Antigravity's `agy`** (the `agy/plugins/fleet-context-filter` plugin, #546), and **Copilot CLI** (`copilot-hooks/fleet-context-filter.json` → `preToolUse`+`modifiedArgs`, #547 — verified non-interactive; interactive TUI hook delivery is an upstream unknown). It is wired but fail-open on **Codex** because Codex presents an updated command's ordinary nonzero exit as `Hook failed`; retaining rewrite would falsely blame the hook, while forcing exit 0 would hide a real command failure (#755). It is explicitly inert on Grok, whose PreToolUse can only allow/deny, never rewrite. The compressor is pure Python (`context_filter.py` + `context_filter_cli.py`), skips streaming/destructive/pipe-heavy commands, fails open, prunes rewrite blobs after 7 days, and carries a reproducible fixture eval. |
| `restart_and_verify_webapp.py` | slash command `/restart-webapp` | Project-aware: looks up the webapp port from `projects.toml`, kills only that PID, then brings the webapp back — via the project's `restart_cmd` (a `WebappManager` respawn the tray adopts, for tray-owned apps) or `tray.bat` — and polls `/api/version` until `git_sha == HEAD`, reporting the new `asset_hash`. Never touches the `:8446` session-host. Three outcomes, never two: exit **0** identity confirmed, exit **2** never converged, exit **3** `UNCONFIRMED` — the app is up but no `git_sha` was readable (missing key, `null`, `""`, or an unreadable HEAD), which used to report as a verified match (fleet-config#562). |
| `notify_on_idle.py` | `Notification` | **Claude Code only** (no other agent exposes this event — Codex/Pi coverage tracked in #213). Opt-in (off unless a project/`[global]` `telegram_chat` is set): pings Telegram via `notify_send` when a live session is **blocked** on input (a permission gate or `AskUserQuestion`) with `🔔 Claude Code awaits your input`, so an AFK human gets a phone notification — routed to the `coding alerts` chat (issue #139). No-ops on the 💤 idle nag. Also upserts the session's Fleet-Board row (`needs-you` / `idle`) via `session_state` before any gating, so board state persists even where pings are off. When `board_url` is also configured (fleet-config#242), the ping appends a `📋 Open on the Board` deep link (`?board=<transcript_uuid>`) — unset by default until app-launcher#307's card resolver ships (see `docs/telegram-workflow.md`). |
| `session_state.py` | `UserPromptSubmit` / `Stop` / `SessionEnd` | Persists `~/.claude/hooks/state/sessions-state.json` for the Fleet Board (#91 ↔ app-launcher#164): one row per recent Claude Code session — `project`, `status` (`working` on prompt submit, `needs-you` on stop, `needs-you`/`idle` via the `notify_on_idle` piggyback), `transcript_path`, `cwd`, `updated_at`, explicit `agent`, optional `launcher_session_id` (#345), and `name`/`name_source` (#302). App Launcher injects `APP_LAUNCHER_SESSION_ID` / `APP_LAUNCHER_AGENT` into child processes so consumers can claim those rows by exact id + agent; external sessions omit the launcher id and fall back to agent-aware cwd matching. The live title comes from `~/.claude/sessions/<pid>.json`, matched by `sessionId == session_id`; `name_source: "derived"` marks the still-generic `<project>-N` fallback. `SessionEnd` (clean exit) **deletes** the row; hard-kill leftovers age out via the 24h writer prune and consumer liveness checks. Atomic writes, always exits 0; missing identity/title inputs never block. **Codex and Pi write into the same file** (#349) via their own thin adapters — `session_state_codex.py` (wired into `codex-hooks.json`'s `UserPromptSubmit`/`Stop`/`PermissionRequest`) and `session_state_pi.py` (shelled out to by the `pi/extensions/session_state.ts` extension on `input`/`agent_settled`/`session_shutdown`). **Grok writes into it with no adapter at all** (#491): it reaches this module through Claude's own settings-file wiring, so only its payload needed translating (`_lib.normalize_payload()`), and its identity rides in the payload rather than a `default_agent` — attribution precedence is `APP_LAUNCHER_AGENT` → payload harness hint → `default_agent` → `claude`, so an external Grok session is recorded as `grok` rather than claiming to be Claude. See [`docs/session-state-capability-matrix.md`](session-state-capability-matrix.md) for exactly which states each agent can prove and why the rest degrade to the Board's `unknown` fallback. |

The context-filter spike is validated by a fixture benchmark, not vendor claims. Reproduce it with:

```powershell
E:/automation/fleet-config/.venv/Scripts/python.exe hooks/context_filter_cli.py eval --fixtures tests/fixtures/context_filter
```

The benchmark reports raw vs compressed token estimates, line counts, latency, and golden-string failures for representative outputs (`pytest`, `npm test`, `git status`, `git log`, logs, JSON). Telemetry (shadow **and** rewrite modes) writes JSONL to `%USERPROFILE%\.fleet-context-filter\shadow.jsonl`, rotating at 20 MB to a single kept generation (`shadow.jsonl.1`, #549 — the launcher's stats totals reflect the current generation and reset at rotation); rewrite mode caches raw outputs under `%USERPROFILE%\.fleet-context-filter\blobs\` unless the output looks secret-like, pruning entries older than 7 days. A measured comparison against the third-party alternatives (chop, RTK, Context Mode, token-optimizer-mcp) — static corpus, live A/B agent sessions, trust gates — lives in [`docs/token-reduction-eval.md`](token-reduction-eval.md) (#219: the native filter won).

**Wrapper timeout.** Because the hook runs the real command as a child, it owns that command's timeout: `FLEET_CONTEXT_FILTER_TIMEOUT` seconds (600 by default; a malformed value degrades to the default). On expiry it kills the **whole process tree** and returns `124` — killing only the direct child leaves a grandchild holding the output pipes, and the capture then blocks forever (fleet-config#411). The two failure modes are reported distinctly: `process tree killed` vs `a descendant still held the output pipes — capture abandoned`. On timeout the recovered stdout also gets an unmistakable **in-band trailer** — `[fleet-context-filter: OUTPUT TRUNCATED - killed after Ns; content above may be incomplete]` — so a consumer parsing stdout as the command's real output can never mistake a truncated capture for a complete one, whatever the exit code says (fleet-config#424). Deterministic helpers shipped with a skill are exempt from wrapping entirely: `rewrite_decision` skips any `.py` under a skill directory, since their whole purpose is one payload the orchestrator reads directly. That covers the shared `skills/_lib/*.py` sweeps (`fleet_audit_scan.py`, `design_sweep_scan.py`, `fleet_repo_scan.py`, `cert_drift.py`) and the longer-running per-skill helpers beside their own `SKILL.md` — `.claude/skills/fleet-health/capture.py` blocks for `POLL_CHUNK_S = 540` seconds by design, and `.claude/skills/system-map/build_data.py` crawls every repo in the fleet (fleet-config#427). Ordinary commands are unaffected and still wrapped.

**Graduation (#392, complete).** The 12-day shadow period reviewed clean — 4,835 rows, 60.0% overall would-save, zero negative-reduction rows, max wrapper latency 15 ms — and the filter has been in **`rewrite` fleet-wide since 2026-08-02** where the harness can preserve command status correctly. The switch is the **mode file** `~/.fleet-context-filter/mode.json` (`{"mode": "off"|"shadow"|"rewrite"}`), owned by the app-launcher Settings panel (app-launcher#713: three-mode control, per-harness applicability matrix, savings stats, plus a Coding-tab saved badge); `FLEET_CONTEXT_FILTER_MODE` in a process env overrides it (kill-switch: set `off`, or flip the toggle — a Claude session started before a settings/env change keeps its inherited env until restarted). Active on Claude Code, Pi (#545), Antigravity's `agy` (#546), and Copilot CLI (#547, non-interactive verified — TUI hook delivery is an upstream unknown); Codex is wired but fail-open because rewritten command failures are misattributed to the hook (#755), and Grok is inert because its PreToolUse is allow/deny-only. Rows carry `ts`, `mode`, `agent`, `session_id`, `cwd` alongside `command`, `raw_tokens`, `compressed_tokens`, `reduction_pct`, `duration_ms`, `exit_code`, and are written in **both** shadow and rewrite modes — the launcher stats panel reads them. When reviewing: watch overall would-save totals, any negative `reduction_pct` (fails open, but flags a rule gap), and unexpectedly large `duration_ms`. Quick summary:

```powershell
E:/automation/fleet-config/.venv/Scripts/python.exe -c "import json,pathlib,statistics as s; rows=[json.loads(l) for l in (pathlib.Path.home()/'.fleet-context-filter'/'shadow.jsonl').read_text(encoding='utf-8').splitlines() if l.strip()]; print('rows', len(rows)); print('median reduction', round(s.median([r['reduction_pct'] for r in rows]),1), '%'); print('raw->comp tokens', sum(r['raw_tokens'] for r in rows), '->', sum(r['compressed_tokens'] for r in rows)); import collections; print('negative-reduction commands:', [r['command'][:60] for r in rows if r['reduction_pct']<0][:10])"
```

Alongside the hooks, `hooks/notify_send.py` is a shared **Telegram-notify transport** (importable + CLI, stdlib-only) any skill / hook / unattended job can call to fire a real bot-identity notification — zero install via the `hooks/` junction. It posts text (`chat.postMessage`) or **uploads a file** (`--file`, via Telegram's external-upload flow) — e.g. `/system-map` posts its rendered PNG with it.

On top of it, `hooks/notify_complete.py` is the **deterministic skill-completion ping** the `issue-*` / fleet skills call (`--kind add|start|finish|yolo|batch|audit|cleanup|recap|finish-batch|learning|design`): it builds the one canonical message and pulls the real GitHub link from `gh` in Python rather than letting the model paraphrase. Every machine→me ping carries an **intent category** routed to a dedicated chat (issue #139) — `coding alerts` for act-now pings (blocked-on-input, `start`/`batch`/`cleanup`-with-review) vs `coding log` for the activity record (filed/shipped/merged, the `/system-map` image, the `/insights-weekly` digest) — single-sourced in `_lib.resolve_notify_target(cwd, category=…)`, which falls back to `telegram_chat` when a category chat is unset. There is no mention machinery: Telegram pushes every message to a chat you are in, so Slack’s `<@user>` tag and its toggle were deleted, not ported (fleet-config#540).

The PR-shipping kinds (`finish` / `yolo`) append a **work-summary roll-up** under the canonical line — the file/LOC shape of the merged change (`📊 +N −M · K files` + new/changed/deleted buckets) — computed deterministically by `hooks/work_summary.py` from `gh pr view` (no LLM). Its CLI (`E:/automation/fleet-config/.venv/Scripts/python.exe hooks/work_summary.py --pr <N|url>`) additionally prints a churn-sorted **per-file table** that `/issue-finish` and `/issue-yolo` echo into the chat report; the table is chat-only (Slack mrkdwn has no tables). Both degrade to nothing on any `gh` error, so a stats hiccup never blocks a finish.

**Every `--summary` / `--text` a skill authors stays pure ASCII** (emoji aside) — a Windows command line is not a UTF-8-safe channel (fleet-config#507): a multi-part summary spells its separator with the ASCII token `|`, `notify_complete.normalize_summary()` renders the `·` from a Python source literal, `_lib.repair_mojibake()` recovers the still-recoverable half on both helpers, and the acceptance matrix fails on any skill or doc that re-inlines non-ASCII punctuation into one of those arguments. The full Slack story (bot helper vs session hook vs the native "Claude in Telegram" remote control, plus one-time setup) is in [`docs/telegram-workflow.md`](telegram-workflow.md).

Two more **project-wired** hooks (opt-in per project via `projects.toml` `capture = true`; currently just life-os, and wired from that project's own `settings.json` rather than user-scope) form a **conversation-memory engine**. `conversation_capture.py` (Stop) writes each finished session to markdown; `conversation_index.py` then digests *settled* captures — once per conversation, after it ends — into a per-folder `index.md` (topic / decisions / open loops, pointing back at the raw capture), so a consumer knows what happened recently without bulk-loading transcripts. Two triggers invoke it (fleet-config#673): `conversation_capture.py` itself spawns it detached, ~60s after every Stop write, so a closed conversation is digested near close rather than only at the next session (the delay clears the indexer's own 45s settle window, and repeated per-turn triggers during an active conversation are cheap no-ops — the settle window and an unchanged-mtime check skip anything not actually ready); `session_index.py` (SessionStart) is the original trigger and now the fallback/catch-up path, in case the delayed run's detached process never gets to fire. The digest goes through `hooks/hub_client.py`, the shared stdlib-`urllib` client for the local LLM hub (OpenAI-shape, fail-open — mirrors `notify_send`). Routing is config-driven: `capture_routing = "flat"` (one `conversations/` + `index.md` per project, the default) or `"skills"` (per-skill dirs, routed by an `active_marker`; life-os's setup). Generic by design — any repo opts in with one `projects.toml` block.

Each capture also carries a machine-readable identity line — `<!-- capture sid="…" agent="…" -->` — holding the **full** session id (the filename keeps only its last 8 chars, enough to dedup a capture but not to reopen one). That id is what makes a specific past conversation resumable: `conversation_index.py` lifts it into the `<!-- idx -->` attrs and into an `index.json` twin written by the same function, and `conversation_search.py` searches every skill at once over two weighted layers — the digests (high) and the full transcript text (low) — returning each hit's ready-to-run resume command (`claude --resume <sid>`, `codex resume <sid>`). The SQLite FTS5 database is a pure derivative of the captures plus the index, kept current at the end of each indexer run: **deleting it is always safe**, `--rebuild` recreates it. A capture with no stored id is reported as searchable-but-not-resumable rather than given a guessed one — the honest state for the handful written before the transcript store's own retention floor, whose identity is gone for good. (A run-once `heal_capture_sids.py` backfilled the rest from Claude Code's transcript store and was deleted once life-os's history was healed, per #598; `git show` recovers it if another project ever opts into capture with pre-header history.)
