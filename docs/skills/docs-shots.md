# `/docs-shots`

- **`/docs-shots`** — the **judgment + orchestration** half of a repo's visual-docs screenshots; the deterministic capture engine (Playwright, fail-safe masking, the manifest, README generator) lives per-app, pinned to the shipped reference implementation `content-management`'s `config/doc_capture/`. Activates only when a repo has `docs/screenshots/manifest.json` (`skills/_lib/docs_shots_plan.py discover`), else a silent no-op. Two entry points: standalone `/docs-shots [feature ...]` (a deliberate refresh — all features or named ones) and a Step-2b sub-step inside `/issue-finish` that intersects the PR diff against each feature's `source_globs` (reusing `ux_surface.py`'s glob matching) to build a stale set with reasons, plus surfaces any changed file under a manifest-covered directory matching no feature as a candidate for a new manifest entry. **Always propose-then-capture** — the engine never runs without the user's explicit OK — and the fail-safe mask guard (a feature with no `mask` selectors is refused, never captured raw) is entirely engine-owned; this skill only surfaces that verdict, never re-implements the guard. Report-only on its own initiative: never edits `manifest.json`/the README block by hand, never commits, pushes, or restarts.
