# Skip delta (a gate that covered less, saying so)

`skills/_lib/skip_delta.py` closes the merge-verification half of the same "merged is not shipped" family: the chief verifies a merge from a **fresh detached checkout** of the merged default branch — never a feature branch, never a worktree whose `.venv` is a junction into the primary's real venv — and that guarantee silently costs coverage. A fresh checkout has none of the repo's gitignored runtime files and none of the host state keyed to a known path, so tests that need either **skip** instead of failing, and pytest prints the same green as a run that covered more. Measured on the 2026-09-12 app-launcher merge round: skips went **17 → 19**, the entire delta being the `#444` real-agent pin. Its residual cause is **agent folder trust** — a never-opened directory paints Claude Code's trust prompt instead of the composer, and `--dangerously-skip-permissions` does not clear it — not the gitignored `config/webapp_config.json` registry (`app-launcher#932`, PR #937). The lane's own words — *"a skip is not a pass"* — were right, and nothing in the gate output named the two tests that stopped running. This is the fleet's recurring shape one level up: **a check that could not establish a fact reporting the same green as one that did** (fleet-config#846). The helper is a pure parser + comparator over pytest terminal output — it runs nothing, spawns nothing, touches no git: `capture <output> --label NAME --out baseline.json` records one run (skip count + named skips, from the `-rs`/`-ra` short-summary block, falling back to `-v` per-test lines; the short-summary block wins outright so a `-rA` run is never double-counted), and `compare <output> --baseline baseline.json` reports the second run against it. Both accept `-` for stdin. It reports the **count** fact and the **set** fact separately, because they fail independently and folding either into the other is the exact defect it exists to close: `STATUS=SAME|INCREASED|DECREASED|UNKNOWN` (`UNKNOWN` = no summary line was parseable, so no count was established — never rendered as "no increase") and `SET=SAME|CHANGED|UNCONFIRMED` (`UNCONFIRMED` = pytest was not asked to name its skips, so a same-count-different-set loss cannot be ruled out), plus `NAMES=complete|partial|none` and a `NEW=` line naming every test that stopped running. Report-only, always exits 0 — callers key on `STATUS`/`SET`, same contract as `dirty_tree_check.py`. Wired into `/chief`'s merge-verification section; pure-logic unit-tested (`tests/test_skip_delta.py`, reached from the one acceptance gate). **Recorded as rejected:** provisioning a credential-free runtime registry so a scratch checkout can run those tests (fleet-config#846's option 2). `app-launcher#932` measured that no registry could close the delta: its launch-id half was fixed credential-free in PR #937, and the residual folder-trust half is not fixable from a test harness, which must neither answer the trust prompt nor write the user's global `~/.claude.json`. The standing rule stays that no path may copy a live credential-bearing config into a scratch checkout (`app-launcher#907`/PR #911). Reporting the loss and accepting the reduced coverage is the fix.
