# `/design-sweep`

- **`/design-sweep`** — the fleet-wide, unattended half of `/design-sync` (fleet-config#180): a scatter-gather wrapper that runs the per-repo design-drift check across every FastAPI + static-PWA web app under `E:\automation\`. One deterministic Python sweep (`skills/_lib/design_sweep_scan.py`) reuses `/audit-fleet`'s filesystem crawl and `design_lint`'s own token detection to gate the fleet down to its token-styled web apps — skipping non-web repos and Streamlit POC spikes — then dispatches one **Sonnet** sub-agent per app (a ≤4 pacing window; Sonnet is exempt from the ≤3-Opus cap) running `/design-sync` report-only, and emits one combined digest (stdout + a `🎨 Design sweep` Telegram ping via `--kind design`). Unlike `/audit-fleet`'s cheap orchestrator, this one runs at **`hard` tier (Opus)** — the enumeration/gating/digest reasoning is where a mistake is most expensive — so only ever the one Opus orchestrator is in flight. It owns **no** week-over-week ledger: the durable design-drift accounting lives in the single `audit-fleet digest state` ledger, where `/audit-fleet` tallies open `design-drift` + `cert-drift` issues per repo on a **separate baseline line**, alongside the six code buckets but never conflated with them. This sweep is the *doer* (files/refreshes the per-repo issues, which `/cleanup-fleet design-drift` then clears); `/audit-fleet` is the unified *reporter*. Built to run unattended on a weekly app-launcher job.
