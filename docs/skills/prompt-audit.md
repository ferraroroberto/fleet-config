# `/prompt-audit`

- **`/prompt-audit`** — the **prompt-quality lens** on the same files `/context-audit` sizes and `/context-purge` compresses: every fleet instruction file (`global-CLAUDE.md`, the `project-scaffolding` master, each repo's `CLAUDE.md` / `AGENTS.md` / `.claude/rules/*.md`, every `SKILL.md`) checked against the vendors' *current* prompting guidance, whose headline is "delete the scaffolding written for older models" (ALL-CAPS pressure, forced verification, step-by-step reasoning scripts, blanket tool defaults) plus hygiene both vendors now ask for (size caps, no contradictions, reasons behind rules). Three phases. A **freshness gate** first: the session fetches each vendor page's verbatim `.md` twin listed in `.claude/skills/prompt-audit/sources.toml` and `audit.py diff-source` hashes it against its baseline (`unchanged` / `changed` / `new-guide` / `not-checked` — an unfetched page is never `unchanged`); any change drafts the `rules.md` delta and new baselines into one `enhancement` issue, and the scan still runs against the current `rules.md`, marking each finding whose rule cites a changed guide as provisional (skipping the scan on a guide change would starve the audit of findings). Then a **scan**: `audit.py` enumerates the surface from `fleet_repos()` (worktrees excluded), plans it against the skip-unchanged ledger (per-file sha under the `rules.md` rubric sha — a rule-set edit forces a full rescan), counts exact lint hits, and easy-tier judgment workers confirm or reject each hit and add the semantic findings (`violation` / `consider` / `compliant` / `unmeasured`). Which vendor's rules are primary is decided by the **file's audience**, not the host — `[audiences.*]` in `sources.toml` plus `*(… only)*` section markers — so single-vendor advice is at most `consider` in a file several agents read. Findings shared with the scaffolding master collapse to one entry with a `propagate to:` list. **Outputs:** one digest comment (`status=complete|partial`, `guides=…`, scanned/skipped/unmeasured, findings by rule) on the audit-managed `prompt-audit ledger` issue (`kind=prompt-audit`, `audit-meta`), whose body carries the guide baselines and the hidden file-hash table; cadence state in `~/.claude/prompt-audit/state.json`; and `audit.py drift`, which upserts one `audit: prompt-drift findings` issue per repo (`kind=prompt-drift`, label `prompt-drift`) from the run's **violations only** — considers stay advisory in the digest — with shared scaffolding text filed once on `project-scaffolding`, each item tagged easy/hard by `/cleanup-fleet`'s prompt-drift tier rule, and the `/codebase-audit` living-backlog merge on re-runs. A delivered run then sends one ASCII activity-log line (`audit.py ping` piped to `notify_send.py --category log`). A failed send is reported as `PING=not-delivered` and never turns a delivered run into a failure. Read-only on instruction files; `/cleanup-fleet prompt-drift` does the fixing. Runs unattended weekly (`run-weekly.bat` → app-launcher Job slotted ahead of `cleanup-fleet-all`, so the `prompt-drift` bucket is fresh when cleanup starts); a rate-gate check precedes the judgment fan-out, and delivery is **asserted, not assumed** — `delivery_check.py` fails the job unless a fresh digest's `<!-- prompt-audit-digest … -->` stamp reports `status=complete` *and* `scan=posted`, plus `update-issue=#N` when `guides=changed`, while the skill itself prints `SCHEDULED-RUN-FAILED` (exit 123) on anything it could not deliver.
