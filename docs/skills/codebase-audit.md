# `/codebase-audit`

- **`/codebase-audit`** — read-only quality sweep of the resting codebase against its `CLAUDE.md` and senior-dev standards. Bundles findings into at most 7 GitHub issues (one per fixed bucket: duplication, stale/dead code, CLAUDE.md drift, maintainability, slop — AI-generated bloat whose volume doesn't earn its keep — bugs, and documentation — README/`docs/` that drift from `CLAUDE.md`, repeat themselves, go stale, or omit a shipped feature), self-assigned, deduped against open issues, with a stricter filing bar for the bugs and documentation buckets, the two that historically re-surfaced the most low-value noise (fleet-config#251). An eighth kind, **security**, is *not* a public checklist bucket — a gap sitting in a public issue is itself a disclosure — so it is self-healed in place (step 8b: a redacted issue with no vulnerability detail, one branch fixing every gap with a mandatory regression test, generic commit/PR text, auto-merge only on a green gate, a private `--kind security` review alert, and escalate-not-merge on any failure). Complements the diff-scoped `/code-review` / `/simplify` / `/security-review`.
  - **Idempotence.** A per-repo `audit-meta` **ledger issue** records the audited **default-branch** commit SHA + rubric hash — never the working checkout's `HEAD`, which the squash-merge + delete-branch pipeline destroys (fleet-config#567) — so a re-run over an unchanged repo short-circuits before reading any files. `audit_issue.py ledger-write` is the single entry point that composes *and* upserts that block, so the agent never hand-writes the sha or the delimiter (fleet-config#566): it records the verified default-branch commit and refuses rather than guessing, accepts either marker form while normalizing every write back to the canonical one (a drifted ledger self-heals), and refuses a body that wouldn't parse back. A ledger the gate can't read — unparseable block or unresolvable baseline — routes the repo to a full audit under its own distinct reason (the scan's `broken_ledgers` field), named in the sweep plan line and the digest so a recurring weekly cost can't masquerade as organic change; `fleet_audit_scan.py`'s `accounting` block asserts the buckets sum back to the repos enumerated so none can vanish.
  - **Skip rules**, so a repo is never re-flagged for churn it caused itself: `SKIP_SELF_FIX` when its only commits since the last audit are `/cleanup-fleet` (or self-healed security) fixes for its own findings, detected via merged-PR `closingIssuesReferences` against its managed bucket issues; `SKIP_BELOW_THRESHOLD` when organic commits — weighted by conventional branch type (`feat`/`refactor` full, `fix`/`chore` partial, `docs`/`test` none) — haven't yet accumulated past the weighted-LOC threshold into `AUDIT`, with the ledger left untouched so the total keeps accumulating across runs (fleet-config#315). All these decisions are one shared, unit-tested Python sweep (`skills/_lib/audit_issue.py`'s `evaluate_repo` + `skills/_lib/fleet_audit_scan.py` for the whole-fleet pass), not per-repo LLM prose.
  - **Traceability.** Each whole-repo audit posts a counts-only `<!-- audit-snapshot -->` comment to the ledger issue — a per-category findings table (date · sha · the seven buckets · total · security-fix count) — kept off the gate's hot path (which reads only the ledger body), so opening a repo's ledger shows its findings *trajectory* over time. Each managed issue (ledger + one per bucket) carries a hidden `<!-- audit-managed: kind=… -->` marker and is upserted through `skills/_lib/audit_issue.py`, so a re-run merges into the one issue per type rather than filing a duplicate.
  - **Recurring buckets (fleet-config#1513).** `audit_issue.py recurrence` reads the ledger's snapshot rows and flags a bucket non-zero in the last two as `recurring` (an unreadable window is `unknown`, never clean); `upsert` stamps that state on the bucket issue, and `structural-gate` checks a cleanup branch's `Structural-check:` declaration (a path in the diff, or `not encodable: <why>`). Both cleanup flows enforce it on recurring buckets (fleet-config#1520).
  - **Dead-code pre-pass (fleet-config#1527).** Step 5a runs `skills/_lib/dead_code_leads.py leads` — vulture at floor 60 (its fixed score for an unused function, class, method or property; floor 80 finds none), filtered to those four kinds, with framework overrides, test files, decorated routes and fixtures, and the repo's own `[tool.vulture]` / `vulture_whitelist.py` dropped, symbols only a test calls tagged `test_only`, and ruff F401/F841 added for repos outside `[static_ratchet]`. Hits are leads; the agent confirms each with the `refs` caller search (whole-word, over every tracked text file incl. launchers and config) and files it with `Refs:` proof beside the `Quote:`. A vulture that is missing, crashes, times out or prints something unparseable is `not confirmed`, never "no dead code" (exit 3). The report carries `dead-code leads: H hits, C confirmed`. Removal stays with `/cleanup-fleet stale`.
  - **Quoted, and regressions visible (fleet-config#960).** Every new or re-matched finding carries a verbatim `Quote:` of the line it is about, and `skills/_lib/audit_quote.py check` confirms the text exists in the named file before the body is upserted. Anything not `VERIFIED` (`MISMATCH`, `NO_QUOTE`, `UNREADABLE`) is reported as unverified and not filed, because a hallucinated `file:line` still looks valid. A finding that matches an already-ticked item is un-ticked and tagged `_(re-surfaced <date>)_`, and it is counted in its own `resurfaced` column that `/audit-fleet`'s digest carries.
