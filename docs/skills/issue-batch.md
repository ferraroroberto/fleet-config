# `/issue-batch`

- **`/issue-batch <issues>`** — fan a list of GitHub issues (`repo#N` or bare `N`, resolved with one `gh search issues`) out to **one background sub-agent per issue**, each building and verifying its change and then **stopping before push**. All git plumbing runs in the orchestrator first and in sequence: grouping by repo, the isolation decision (in place for a single issue in a repo, a `worktree_claim.py` worktree per issue when several hit the same repo), main-branch sync and branch cutting, so every sub-agent starts on a ready-to-edit tree. It never creates issues, pushes, opens PRs or merges; as each agent returns, the orchestrator runs a post-flight dirty-tree check that only corrects the reported status. Shipping is a separate step: `/issue-finish` per branch, one at a time, or [`/issue-finish-batch`](issue-finish-batch.md) for the parallel finish. The three-lane boundary with `/issue-yolo` and `/quick` is in [`/quick`](quick.md).
