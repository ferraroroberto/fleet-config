# `/design-review`

- **`/design-review <repo> [file] [--no-publish] [--no-judgment] [--judges N]` / `/design-review fleet [file]` / `/design-review <repo> full-app`** — the **rendered** design leg `/design-sync` reports as `unmeasured` (fleet-config#970; core #971, skill + report #972, bounded judgment #973, ledger / filing / fleet #974). Where `/design-sync` reads authored CSS, this one measures a *running* app in real browsers — computed font sizes, WCAG contrast against the composited background, effective hit rectangles, icon boxes, overflow, accessible names, controls per row — on the fixed `iphone` / `android` / `desktop` × light / dark matrix, scores every rule of the versioned `design.rubric.toml` from the numbers, and renders one self-contained HTML report (verdict + grade, scorecard, method and caveats, what is already strong, findings by category with severity / evidence / standard / fix / owner, now-vs-proposed mock-ups, where the fixes land). Deterministic commands, no LLM in the grade: `probe` (pre-flight — a dead port stops the run with the target `CLAUDE.md`'s restart pointer; the skill never starts, restarts or kills anything), `measure` (the read-only walk, ~4 min for app-launcher), `evaluate --out` (rules, scores, grades), `judge-prompt` / `judge-merge` (the bounded checklist), `ledger` (the run entry + diff), `render` (the page), `file` (the managed issue, dry run by default), `fleet` (the serial sweep). Every finding sentence is the rubric's `fix_template` + `standard` with measured values substituted; grades are printed from the JSON, never recomputed; mock-ups are library templates filled from measurements and a rule whose template needs an unmeasured value renders without one and says so. Output lives in `~/.claude/hooks/state/design-review/<target>/<stamp>/` (gitignored); the report is published as a **private** artifact only where the host exposes an artifact tool, otherwise its path is printed, and no screenshot or captured text ever reaches an issue, PR or comment. Between evaluate and render, a **bounded judgment stage** (#973): the rubric's `[[judgment]]` checklist (ten seed questions, stable `J-NN` ids) is answered `yes | no | na` by a fresh-context judge agent that receives only a deterministic prompt file naming this run's local screenshots and `metrics.json` — never a previous report or an expected answer; the reply is schema-validated per answer (fleet-config#1185: a malformed answer is dropped and listed with its reason, the valid ones are kept, `judgment: partial`; an unreadable reply or one with nothing valid is `judgment: unmeasured`), every `no` lands on a rule id from the question's `maps_to` or is an **uncatalogued** finding with a proposed metric + threshold, listed in the report outside the grade; `--judges 2` keeps only agreed answers and lists disagreements as `not confirmed`; `--no-judgment` skips the stage. The skill spawns the judge through the capability contract (`docs/workflow-capabilities.md`), collects it within the turn, and never answers a question itself; on a host with no fresh spawn the stage is *not run* and says so. Then (#974) `ledger` records the run in a local state file (`~/.claude/hooks/state/design-review/<target>/ledger.json`, last 20 kept; ids, statuses, grades, the checkout commit and the live build's sha as two separate facts) and writes the run-to-run **diff** by rule id into `evaluate.json` — fixed / regressed / new / unchanged, with an unmeasured side never counted as either — so the report opens with what changed; the `file` argument opts into **filing**: the app-owned findings are merged into the repo's one managed `design-review` issue through `audit_issue.py` (line per rule id, checkbox preserved, a passing rule marked fixed in place, spec- and scaffold-owned rules never on the app, `[[design.accepted]]` `rule` entries suppressing with a reason), and without it the same body is a dry run beside the report; `fleet` sweeps every declared web app serially — an app not listening is `unmeasured`, never started; judgment skipped; a rule failing in two or more apps promoted to the scaffold list once — into `fleet-digest.json` / `.html`, filing likewise opt-in. `full-app` (fleet-config#1332) is the whole-app redesign review on top of that run: an authored investigation (inventory, one shared system, everything-still-here tables, Step N/M build plan, owner decisions), a local 390px light/dark mockup page, one step per PR with a phone check each, and a mandatory write-back of the learnings into `design.md` / `design.dark.md` and `docs/design-system.md`; the procedure is a section of the skill.
