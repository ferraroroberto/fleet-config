# `/system-map`

- **`/system-map`** — regenerate the fleet **architecture map**: crawl `hooks/projects.toml` (minus `[global] architecture_ignore`), reconcile it against the single source of truth (`architecture/fleet.data.js`) and the narrative doc (`architecture/ARCHITECTURE.md`), render the light Janis-style infographic to `architecture/system-map.png` with headless Chrome via the shared `skills/_lib/html_shot.py` measure-then-shoot helper (placeholder specs only — real hardware specs stay in the gitignored `system-map.local.js`), commit the diff when the map changed, and post the fresh image to Telegram on every run — with a one-line week-over-week **what-changed** summary (`+whatsapp-radar, −suna, 3 repos updated`, from `.claude/skills/system-map/whatchanged.py`). Also renders a **text-native companion** of the same `fleet.data.js`: `.claude/skills/system-map/render_mermaid.py` emits `architecture/system-map.mmd` (a Mermaid flowchart, icons + names only, edges from each card's `tag`) — the fleet-map doc `global-CLAUDE.md` points at rather than embeds, keeping the diagram out of always-on context. Each fleet repo can also carry its own hand-authored `docs/architecture.mmd` (its *internal* structure — modules, data flow, dependencies), referenced from that repo's own `CLAUDE.md`; `fleet-config`'s is the reference example. The acceptance matrix asserts the fleet ⇄ data file ⇄ doc never drift, including the Mermaid render — and, one step upstream, that `projects.toml` itself still lists **every** repo sitting on disk beside this one (`fleet_membership`). That list *is* the fleet-membership definition, so a repo missing from it is silently absent from this map, from `/config-map`, from `/context-audit`'s cap gate and from `chief_ops.py verify` — which is how `local-llm-hub-lite` went six `/cleanup-fleet-all` lanes without appearing in any fleet report. A new repo now fails the gate until it is declared, or deliberately listed in `[global] architecture_ignore`. Built to run unattended on a weekly app-launcher job.
