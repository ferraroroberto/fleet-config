# UX-conformance gate (diff-keyed design check)

`skills/_lib/ux_surface.py` is the second cross-skill primitive — it decides, deterministically, whether an issue's change touched a web app's UX so the issue-workflow skills can gate the fleet design check on the *diff* rather than re-deriving a glob match in three places. A repo declares its surface in a `## UX surface` block in its own `CLAUDE.md` (`design spec applies`, `paths`, `key views`); a repo without one — `fleet-config` itself, any non-web repo, a Streamlit spike — yields `SPEC_APPLIES=no`, so the gate is a permanent no-op there. `applies <repo>` (block only, no git) drives the cheap design-aware spec-load at `/issue-start`; `check <repo>` adds `git diff --name-only <main>...HEAD` and reports `TOUCHED` + the `MATCHED` files for the gate at `/issue-finish` (step 3b) and `/issue-yolo` (Phase 3e). A diff that *fails* (bad base ref, unreadable repo) reports `TOUCHED=unknown`, never `no` — the shared `git_run.changed_files()` returns `None` rather than an empty list precisely so a failed probe can't render as a clean one, and all three diff-keyed gates (`ux_surface`, `deploy_coverage`, `docs_shots_plan`) treat `unknown` as touched. When the diff *did* touch UX, the gate fixes material token drift in-branch (not file-and-defer — that's `/design-sync`'s periodic job) and visually verifies the touched view via the repo's own launch skill, else Claude Code's built-in `run` skill. **The screenshot is inspected in-session only and never attached to a PR/issue/comment** — every repo is treated as public, so an uploaded UI screenshot is an information breach; the PR carries a text-only conformance line instead. Its block parser, brace expansion, glob→regex, and diff intersection are pure-logic unit-tested (`tests/web_review/test_ux_surface.py`, reached from the one acceptance gate).

## Visual proof (merge gate)

`ux_surface.py check` counts more than the block's declared `paths`: once the spec applies, view JS under `static/`, templates and Streamlit pages count too (`DEFAULT_UI_PATTERNS`, test fixtures and `docs/` excluded), because what renders changes when they do, not only when the CSS does.

A UI-touching diff ships with proof the agent looked at its own work. `skills/_lib/ui_proof` binds that proof to the tree and answers the finish gate:

```
E:/automation/fleet-config/.venv/Scripts/python.exe C:/Users/rober/.claude/skills/_lib/ui_proof record . --manifest <proof-dir>/manifest.json --criterion "<state>=<criterion>"
E:/automation/fleet-config/.venv/Scripts/python.exe C:/Users/rober/.claude/skills/_lib/ui_proof capture . --phase before --url <gate-instance-url> --state <state> [--viewport phone] [--click <selector>]
E:/automation/fleet-config/.venv/Scripts/python.exe C:/Users/rober/.claude/skills/_lib/ui_proof capture-before . --manifest <main-dir>/manifest.json   # or --image "<state>:phone-light=<png>"
E:/automation/fleet-config/.venv/Scripts/python.exe C:/Users/rober/.claude/skills/_lib/ui_proof capture-after . --manifest <branch-dir>/manifest.json
E:/automation/fleet-config/.venv/Scripts/python.exe C:/Users/rober/.claude/skills/_lib/ui_proof build . --pr <PR> --criterion "<state>=<what changed, where to look>" --title "<issue title>" --issue <N>
E:/automation/fleet-config/.venv/Scripts/python.exe C:/Users/rober/.claude/skills/_lib/ui_proof check . --pr <PR>
E:/automation/fleet-config/.venv/Scripts/python.exe C:/Users/rober/.claude/skills/_lib/ui_proof build . --pr <PR> --sha <merge sha>
```

- **Capture.** Each UI acceptance criterion maps to a named state. project-scaffolding's `tests/e2e/_layout_lint.py` `capture_states` captures it at phone and desktop, light and dark, lints the layout and writes `manifest.json` under `UI_PROOF_DIR` (never inside a checkout). Use one proof folder per issue: the manifest merges across calls, and a state left from other work counts against this branch.
- **Record.** `ui_proof record . --manifest <dir>/manifest.json --criterion "<state>=<criterion>"` (repeatable) stores the manifest's sha256, the criterion-to-state map and the working-tree hash (the gate-evidence hash) at `rev-parse --git-path ui-proof.json`, per worktree and outside the tree.
- **Check.** `ui_proof check .` prints `VISUAL_PROOF=` with one state: `n/a` (no design-gated surface, or the diff touched none of it), `fresh`, `missing` (no record, or a criterion's state lacks a leg), `stale` (the tree or the manifest changed since `record`), `failing` (an unallowed layout-lint error), or `unknown` (the tree hash could not be computed). `NEED=` names what to capture or fix; a failing finding is quoted as kind, element and measurement, never page text. A diff that could not be taken (`TOUCHED=unknown`) needs proof for every key view, and `NEED=` lists them.
- **Enforcement switch.** The gate refuses (exit 1) only where the repo's `.fleet.toml` `[vendored]` table lists `layout_lint` (`ENFORCED=yes`), since a repo without the capture helper cannot produce the proof. Elsewhere a UI diff without fresh proof prints `VISUAL_PROOF=<state> (layout_lint not vendored)` and exits 0. The finisher carries that line into the PR body and the report, so a missing proof is visible, never a silent pass.
- **Proof folder.** Every UI diff, vendored or not, ends with `<repo>/.proof/<PR>/index.html` in the primary checkout. A lane writes only inside the checkout it runs in: a worktree lane's `.proof/` is its own, and `build --pr <PR> --sha <merge sha>` copies the PR folder and its index row into the primary's `.proof/` (`PUBLISHED=`), keyed by PR so a re-run replaces it whole. Until the merge the primary is untouched. `capture` drives a running instance of the app (the gate instance's URL) at named viewports and themes with the repo's own `.venv` Playwright: `phone` is 390x844, `desktop` 1280x900, any `<W>x<H>` or `<label>=<W>x<H>` works, light and dark by default, `--click` selectors reach the state. A repo without Playwright in its `.venv` reads `PLAYWRIGHT_MISSING`, an app that does not answer `APP_UNREACHABLE`, each its own reason. `capture-before` (against `main`) and `capture-after` (on the branch) instead copy screenshots from a `capture_states` manifest, or from `--image "<state>:<viewport>-<theme>=<png>"`; all of them stage into `.proof/_branch/<branch>/`. Once the PR exists, `build --pr <PR>` moves them into `.proof/<PR>/` and writes one self-contained page (inline CSS, `data:` images, no scripts): per state, its `--criterion` lines (repeat `--criterion` with the same state for several checks on one screen) of what changed and where to look, then before and after side by side for each leg; `--no-visual "<criterion>"` gives a criterion with no visual change its one line; the layout-lint result when the after capture came from a manifest, "not run" otherwise. It writes `.proof/index.json` keyed by PR number (`title`, `issue`, `merge_sha`, `utc`, `branch`) for the launcher Board, and copies the page under `%TEMP%/claude/ui-proof/` as `SEND_PATH=` for `SendUserFile` or `send_file.py` (15 MB cap, flagged as `SEND_WARNING=`). After the merge, `build --pr <PR> --sha <merge sha>` stamps page and index, keeping the criteria. It never goes to GitHub; the PR keeps a text-only conformance line.
- **Folder gate.** `check . --pr <PR>` adds `PROOF_PAGE=present|missing` and refuses (exit 1) on a UI diff without the page, and on a `.proof/` that is tracked or not gitignored, whether or not `layout_lint` is vendored: neither needs the capture helper. The built page is itself the proof: with no recorded manifest it reads `VISUAL_PROOF=fresh`, the lint result is whatever its captures carry ("not run" without a manifest), and `NEED=` never asks for a manifest. A page whose captures carry an unallowed lint error reads `failing`. Every repo that can produce a UI diff carries a `.proof/` line in `.gitignore`.
- **Prune.** `prune . --older-than 30d` removes PR and staging folders (and their index rows) whose newest of folder time and index stamp is older than the threshold; nothing else under `.proof/` is touched, and the owner may delete `.proof/` at any time.

Tested by `tests/web_review/test_ui_proof.py`, `tests/web_review/test_ui_proof_store.py` and `tests/web_review/test_ui_proof_capture.py` against a temp repo.
