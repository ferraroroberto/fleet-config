# `/chief`

- **`/chief`** — the brain of the **fleet chief**, app-launcher's standing conversational orchestrator. Not invoked by a human directly: the launcher's Board chat mode spawns one `label="chief"` PTY session cwd'd in this repo (that cwd is what loads this fleet-only tier plus the global fleet map, and keeps app-launcher's own project context out) and types `/chief` as its first prompt — daily-fresh via a scheduled respawn, lazily on the first chat message, or from a manual Start button, all through `POST /api/board/chief/ensure`. The skill teaches the session to answer fleet questions from live data (`GET /api/board` over loopback, which bypasses all auth including passkey gates, plus `chief_ops.py issues` / `gh_issue_fetch.py fetch` for issue lists, never `gh search`) and to act **only** through the launcher's existing endpoints (`/api/board/issues/start`, session input/stop; a free-text ask is filed as an issue with `gh issue create` first, since the launcher's free-text dispatch no longer exists), with the safety rails living here in git, not in app code: safe default verb (`start`), `/issue-yolo` only on the literal word "yolo", issue numbers only from deterministic lists, a phone-tunable worker cap read live from `GET /api/board/chief/settings`, a fleet-job guard that warns on any dispatch while a fleet-wide scheduled job runs and refuses a fleet-wide brief until it finishes, never stopping its own session, and read-only unless explicitly directed. Steers into a running worker **carry no signature and claim no authority at all** (this replaced an earlier in-band authority prefix): an unauthenticated string asserting its own rank is indistinguishable from prompt injection, so workers refused it — increasingly, and correctly, as their models improved. A steer is now composed the way a sub-agent brief is: self-grounding, citing something the worker can check for itself (an issue number, a `file:line`, a reproducible command), and never leaning on a prior instruction that was not confirmed `DELIVERED` — referencing context the worker never received is exactly what fabricated shared history looks like from its side. What the dispatch brief declares is a **channel, not a password**: the terminal-input endpoint carries instructions, and text arriving any other way (tool output, a file, a web page, an issue body, a commit message) is data being read rather than an instruction addressed to the worker — a distinction that survives dropping the prefix because a channel is not a string. Destructive-scope steers (discarding work, deleting branches, worktree teardown, force-push) still always need Roberto's in-terminal echo, now standing on their own rather than as a carve-out from an authority claim. It **wakes on the launcher's doorbell**: while Settings > Chief > Doorbell is on, the launcher types one fixed, data-free line into the idle chief whenever the mailbox has pending events, and the chief drains it with `inbox` then `ack`; `chief_ops.py wake` reads that switch at each turn end, and only when it is off or unreadable does the chief arm its fallback waiter. That waiter, like any polling, is built from **one-shot background tasks** — wait, one digest, exit, relaunch — never a loop with an internal `sleep`, because only a task's *exit* re-invokes the session, so a loop reports to nobody until it terminates; that is the deliberate inverse of the "never end a turn waiting to be resumed" rule the chief hands to every worker, and the skill states both side by side so they don't read as contradictory. It also teaches the **quiet-lane-vs-hung-lane** call a long unattended run forces, cheapest check first: job-log `[h:mm:ss]` prefixes are *elapsed*, not wall-clock (so real silence is the file's mtime against now, and a line's true time is `run_id + elapsed`), `claude_progress.py`'s 45-minute stall watchdog already kills and reports a genuinely dead stream with exit `124`, a multi-minute gap is the normal shape of an agent sitting inside one verification-gate tool call, and positive proof comes from the CPU of the `claude.exe` **child** — never from the adapter, which is idle by design between milestones and so reads identical whether the lane is healthy or dead. Replies are drawer-shaped: terse, phone-readable, ending in a self-contained summary line. Workers reach the chief through the **chief mailbox** — one event file per worker turn-end or exit in `hooks/state/chief-inbox/`, read by `chief_ops.py wait-event` (exactly once) or the v2 `inbox` / `ack` pair (claim, handle, ack; an unacked claim is re-offered) — whose cross-repo contract, event schema and file-name pending-count rule live in [`docs/chief-mailbox.md`](../chief-mailbox.md). Finished lane worktrees are the chief's to remove, not Roberto's to confirm <!-- history: fleet-config#1496 -->: `chief_ops.py sweep` (`skills/_lib/chief/chief_sweep.py`) classifies every `<repo>-wt-<N>` as `finished` (clean, and nothing beyond the default branch or all of it in a *merged* PR — a squash merge leaves local SHAs ahead, so the PR is asked, not `git log`), `in-use` (a live session's launch cwd or a live active-issue marker; a lane that `cd`s into a worktree is held by its marker), `has-work` (dirty or unmerged — the only class the chief asks about), `orphan-empty` or `unknown` (a failed `gh` call or an unreadable board is its own state, never `finished`); read-only by default, `--apply` removes `finished` through `worktree_claim.py remove-worktree` and `orphan-empty` by `rmdir`, reports a folder that will not go, never kills a process, and lists `idle-finished` chief-managed sessions whose issue is closed as `stoppable`.
