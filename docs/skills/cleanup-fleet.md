# `/cleanup-fleet`

- **`/cleanup-fleet <bucket>`** — the fix-half of the audit loop. Takes one bucket label (`documentation`, `claude-md-drift`, `bug`, …), gathers every open issue carrying it across the fleet, scores each for complexity, and fans out **one background agent per repo** sized to the work via the fleet's easy/hard tier policy ([`docs/model-tiers.md`](../model-tiers.md)): easy-tier issues run full `/issue-yolo` → merged (each firing its own PR-link ping); hard-tier issues build → stop for your review (per the doc's tier mapping) — and hand back a plain-English rationale summary (what was done, why, and why it's believed correct) rather than expecting a diff read, surfaced inline when the run reports back. One agent per repo by construction (the audit files one issue per repo per bucket). The ninth bucket, `prompt-drift` (from `/prompt-audit`, #833), tiers by consequence — softening caps, deleting a re-check line, adding a neutrality marker are easy; restructuring a step list, resolving a contradiction, or touching `global-CLAUDE.md`, the scaffolding master, a quoted trigger or a marked block are hard — and every lane must pass `/context-purge`'s preservation harness (`check.py --base`) plus a directive-inventory walk. `hard` mode (default) presents the plan for approval and runs both tiers; `easy`/`silent` mode runs only the easy tier unattended and never auto-merges hard-scored work — safe to schedule after `/audit-fleet`. Once you've reviewed the hard-tier branches, `/issue-finish-batch` ships them in parallel (below).
