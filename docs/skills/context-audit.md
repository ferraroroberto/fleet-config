# `/context-audit`

- **`/context-audit`** — the **always-on context surface** lens, and the home of the context-efficiency standard itself (project-scaffolding#68 — deliberately kept in a skill body loaded only on invocation, because a standard governing the always-on surface must not itself bloat it). Weekly, `.claude/skills/context-audit/audit.py` measures three things and the orchestrator judges them, never re-deriving a count: the **always-on token budget** per `CLAUDE.md` plus the fleet total, week-over-week against the previous run in the ledger; every **skill `description:`** against the ~50-word prose cap (quoted trigger examples exempt, so routing never regresses) across *every* fleet repo's `.claude/skills/*/SKILL.md` — membership from `fleet_repos()`/`hooks/projects.toml`, the same list `/system-map` and `/config-map` read — plus fleet-config's junctioned always-on `skills/` tier; and **single-home-by-altitude violations**, where a universal directive that belongs once in `global-CLAUDE.md` (or a shape-gated one in the `project-scaffolding` master) has been restated verbatim in a project `CLAUDE.md`, along with header drift from the scaffold master. A description that can't be read, carries no `description:`, or whose repo checkout is missing reports as **`unmeasured`** — its own state, never folded into compliant (silently shrinking the working set is what once made `over_cap=0` technically true and completely false, fleet-config#626); a frontmatter a YAML loader would reject or silently truncate reports as **`unparseable`**, likewise never compliant (fleet-config#845). It also measures **bootstrap loads** for a repo declaring its skills' bootstrap in `hooks/projects.toml` (life-os): per skill, the files every invocation auto-loads, with est tokens, **`over-cap`** files (past the read cap, so they load truncated while reporting success), `missing` and `unmeasured`, plus credential-shaped lines counted by file with no values printed (`bootstrap_loads.py`, fleet-config#1014; the convention is `docs/context-assembly.md`). **Prescriptive but read-only**: it upserts the `kind=context-audit` ledger issue, comments the weekly narrative, and pings Telegram — it never edits a `CLAUDE.md`, commits, or pushes; fixes are separate issues routed through `/cleanup-fleet`, and the rewriting counterpart is `/context-purge` below. The **descriptive** sibling is `/config-map`. Runs unattended on a weekly app-launcher job.
