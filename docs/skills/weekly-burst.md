# `/weekly-burst`

- **`/weekly-burst`** — the heavy half of the acceptance suite, run once a week instead of on every change. The per-change gate (`tests/run_acceptance.py`) never runs a burn or load proof; the units that load the CPU on purpose, wait out a real wall-clock bound or spawn in bulk live in `tests/acceptance/weekly/units.py` and run through `tests/run_weekly_units.py`. The burst has three legs, each recorded in the unit ledger (`<hooks state dir>/gate-unit-ledger.jsonl`) under its own label: **units** (`weekly-units`: the weekly units in this working tree), **hermetic** (`weekly-hermetic-units` and `weekly-hermetic-gate`: a fresh detached clone of this checkout's HEAD runs the weekly units and the full gate, so a unit that leans on a gitignored file, the checkout's folder name or a `.venv` only this tree has goes red) and **medians** (per-unit median seconds over the last five `gate` runs). Results are written to `<hooks state dir>/weekly-burst/<utc>.json` with one log per leg, the last eight runs kept, never next to the code. Exit `0` green, `1` any red unit, `3` a leg that could not be established (no clone, no ledger rows), its own state and never a pass.

  **No model.** The run is deterministic, so `run-weekly.bat` calls `burst.py` directly instead of `claude_progress.py`; the exit code is the verdict, and `tests/claude_progress/test_delivery_checks.py` pins that shape. The launcher Job is created in app-launcher's Jobs registry, not in this repo.

  **What moved out of the gate.** `cpu_burn` (starts real CPU burners), `hook_spawn_timeout` (a deliberate 16 s slow start), `fleet_health` (three real 15 s poll sleeps) and `_host_power_codex_unit_checks` (68 hook spawns for one rule). A new burn or load proof is a row in `weekly/units.py`, never one in the gate. The burst holds the box load lock in shared mode like the gate, so `cpu_burn`'s own exclusive acquire still works when nothing else is gating.
