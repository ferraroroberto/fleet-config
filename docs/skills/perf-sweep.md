# `/perf-sweep`

- **`/perf-sweep [repo]`** — the fleet-wide, unattended half of `/perf-review`. `python -m perf_review sweep` (`skills/_lib/perf_review/sweep.py`) walks every web app that is not dormant (`design_review.fleet.fleet_targets`, the population `/design-review fleet` uses): a `hooks/projects.toml` table with a `webapp_port`, or a `working-web` repo whose own `.fleet.toml` declares a `port` — the layer gate keeps an `enabling` lite mirror, which shares its sibling's port, from being measured twice under another name. A repo that looks like a web app yet has no walkable port is named under `## Left out` with its reason, never dropped. Apps run **one at a time**, because a second page load skews the first's timings. Each app is measured and filed by the same `measure` and `file --apply` a single `/perf-review file` runs, so the run lands in the ledger and its managed `perf-review` issue is opened, refreshed or closed by the same rules (an all-green app files nothing). The skill only starts the command, waits for it inside its own turn (about 7 minutes per app) and relays the digest.
- **Quiet box only.** Each app is timed under an exclusive `box_lock`, so no lane gate loads the machine meanwhile and a measurement never starts under load. The lock is fair (queue tickets), so a gate waiting behind the sweep takes the gap between two apps and the next app waits for that gate. An app whose lock stays busy past `--lock-wait` (20 minutes) is `unmeasured` with `BOX_BUSY`.
- **Never restarts.** A port that is down, an app that fails to measure or a box that stays busy is `unmeasured` with its reason, never a pass, and nothing is started, restarted or killed. An unmeasured app files no issue and leaves an existing one alone.
- **A stalled window is unknown, not slow.** An app whose every timed route (three or more, `/` included) went over its p95 budget in the same window is reported `unmeasured` with `machine busy` in the `## Unmeasured` section, and nothing is filed from it: the sweep shares Saturday nights with backups, and a stall across routes that do no work is the box, not the app. One slow route still reads over budget.
- **Idle sample.** Before each app's page load, while nothing of the sweep is hitting it, `perf_review/idle_sample.py` watches the app's own process tree for `--idle-window` seconds (60; 0 skips): the tree is rooted at the PIDs netstat reports listening on the app's port, and the process table is read about every 3 s. The figures are CPU seconds a minute (growth of every tree member, a child counted from birth) and processes started a minute (tree members created inside the window; a child that lives under one read interval can be missed, so the count is a floor). Read-only: no restart, stop or signal. An app with no listener, an unreadable table, or a listener replaced mid-window has no figure and reads `unknown`, never 0; unknown samples are not stored. Measured samples append to `~/.claude/hooks/state/perf-review/idle.jsonl`, and the next run compares against the latest one. A rise is flagged when a figure grew at least 1.5x and by at least 1 CPU s/min or 1 process/min (`RISE_*` constants in `idle_sample.py`).
- **The digest** (stdout, and `~/.claude/hooks/state/perf-review/sweep-<UTC stamp>.md`, printed as `DIGEST_FILE=`): a counts line (pass, over budget, unmeasured, slower than the last run), one table row per app (result, the over-budget checks with measured vs budget, regressions and slower p95s from the `DIFF` against the last run, whether the app serves an older build than its checkout, the issue it was filed to), three idle columns (CPU s/min, processes/min, and the change since the last run, flagged `RISE`), an `Idle load rose` line, then the `## Unmeasured` reasons and the `## Idle sample unknown` reasons. Repo names, check ids and numbers only. Exit 0 when at least one app was measured, 3 when none was, 2 when nothing is in scope.
- **Flags.** `--only <repo>` (even a dormant one), `--duration` seconds of endpoint timing per app (300), `--settle`, `--idle-window`, `--lock-wait` minutes (20), `--no-file` to measure without touching an issue.
- **Scheduled** by an app-launcher Job calling `.claude/skills/perf-sweep/run-weekly.bat`; the schedule itself lives in app-launcher's `config/jobs.json`, not here.
