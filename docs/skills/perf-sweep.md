# `/perf-sweep`

- **`/perf-sweep [repo]`** — the fleet-wide, unattended half of `/perf-review`. `python -m perf_review sweep` (`skills/_lib/perf_review/sweep.py`) walks every `hooks/projects.toml` web app that is not dormant (`design_review.fleet.fleet_targets`, the population `/design-review fleet` uses), **one at a time**, because a second page load skews the first's timings. Each app is measured and filed by the same `measure` and `file --apply` a single `/perf-review file` runs, so its managed `perf-review` issue is refreshed with the run. The skill only starts the command, waits for it inside its own turn (about 7 minutes per app) and relays the digest.
- **Quiet box only.** Each app is timed under an exclusive `box_lock`, so no lane gate loads the machine meanwhile and a measurement never starts under load. An app whose lock stays busy past `--lock-wait` (20 minutes) is `unmeasured` with `BOX_BUSY`.
- **Never restarts.** A port that is down, an app that fails to measure or a box that stays busy is `unmeasured` with its reason, never a pass, and nothing is started, restarted or killed. An unmeasured app files no issue.
- **The digest** (stdout, and `~/.claude/hooks/state/perf-review/sweep-<UTC stamp>.md`, printed as `DIGEST_FILE=`): a counts line (pass, over budget, unmeasured, slower than the last run), one table row per app (result, the over-budget checks with measured vs budget, regressions and slower p95s from the `DIFF` against the last run, whether the app serves an older build than its checkout, the issue it was filed to), then the `## Unmeasured` reasons. Repo names, check ids and numbers only. Exit 0 when at least one app was measured, 3 when none was, 2 when nothing is in scope.
- **Flags.** `--only <repo>` (even a dormant one), `--duration` seconds of endpoint timing per app (300), `--settle`, `--lock-wait` minutes (20), `--no-file` to measure without touching an issue.
- **Scheduled** by an app-launcher Job calling `.claude/skills/perf-sweep/run-weekly.bat`; the schedule itself lives in app-launcher's `config/jobs.json`, not here.
