# `/e2e-audit`

- **`/e2e-audit`** — **on-demand** e2e/regression test-suite redundancy audit (fleet-config#406), deliberately **not** a weekly job — suite bloat is feature-driven, not time-driven, and the fleet already runs six skills weekly. Its recurring trigger is feature-driven too: `/e2e`'s budget step (`e2e_test_audit.py budget`, fleet-config#901) measures collected nodes against `.fleet.toml` `[e2e] test_budget` (default: the scaffold's 15) on every finish, and runs this audit when the suite is over budget with no open `e2e-redundancy` issue. A budget-triggered run that confirms nothing still files one finding, a `test_budget` ratchet at the current size, so a structurally large suite is not re-audited on every finish (fleet-config#905). Runs the deterministic `skills/_lib/e2e_test_audit.py` scan: resolves the repo's test dir from its `## CI expectations` CLAUDE.md block (falling back to `tests/e2e/`, the shared convention `project-scaffolding`'s `docs/playwright-ui-testing.md` establishes), inventories test files, counts both raw `def test_` functions and the true pytest-collected node count (parametrize-expanded), clusters near-duplicate test names, flags **same-file tests sweeping the same `@pytest.mark.parametrize` matrix** (the blind spot name clustering can't see — differently-named twins over one shared `MATRIX` collide on nothing, which is how a confident "0 clusters" over 32 collected nodes once closed `project-scaffolding#209` before PR #219 collapsed the same tests to 8 with no coverage loss; fleet-config#602), flags file-size outliers, and — when the repo declares a `## UX surface` block — cross-references declared key views against test coverage. A `## CI expectations` heading **inside a fenced code block** is ignored, so a repo that only *documents* the block template isn't read as declaring one; and a scan whose test dirs resolve to nothing on disk reports `test_dirs_resolved: false` — an explicit *unknown*, never folded into "no tests". LLM judgment is confined to confirming each candidate cluster/gap is real (never re-deriving a count) before filing exactly one deduped `e2e-redundancy` issue through the same `skills/_lib/audit_issue.py` machinery as `/codebase-audit`/`/design-sync` — a first-class audit bucket `/cleanup-fleet e2e-redundancy` fans out fixers for. **Report-only, never rewrites or deletes a test** — the review half of the split with `/e2e` (which owns execution + in-branch maintenance, fleet-config#556). First validated against `app-launcher`'s `tests/e2e/` (~400 collected nodes vs. `playwright-ui-testing.md`'s explicit <15-test target). **Value and time, not just size** (fleet-config#1018): node count is not the cost (app-launcher's #1215 trim cut nodes 18% and browser time 3.5%), so `e2e_test_audit.py timing` reads the last completed gate run's progress log (`.fleet.toml` `[e2e] progress_log`, else `[e2e] junit_xml`, via the `skills/_lib/e2e_value/` package) for per-phase, per-projection and per-module time, the duration buckets, the tail share, static cost drivers (page loads, PTY references, real-agent marks), whether another checkout's run overlapped it (`loaded`), and runtime figures in CLAUDE.md/README more than 25% off; `failures` collects every red in the logs on disk plus merged-PR and `bug`-issue mentions (a lower bound) and lists **race candidates**, tests red at two or more different steps, which are never filed as flakes by default (app-launcher#1222). `routing` routes the last 60 merged PRs through the repo's own imported `classify_e2e.py` (tiers, forcing classes and single causes, shadowed and unclassified paths, a `--proposed` counterfactual); `parallel` lists static xdist blockers, projects the last serial run onto 2/3/4/6 workers (LPT with load inflation) and names tests red only under workers as shared state. No log is `unknown`, never an estimate; it never starts a gate. **Trigger on growth** (Roberto's 2026-09-25 decision on #1018): `e2e_test_audit.py budget` also prints `E2E_TIME_BUDGET` (the browser leg of the latest quiet full-tier run against `[e2e] time_budget_s`), `E2E_GROWTH` (test functions since the last audit's `record`, kept in machine-local hooks state) and one `E2E_AUDIT_TRIGGER=yes|no|unknown`, so `/e2e` 6b audits a suite that is over either budget or has gained ~10 tests, with #406's no-clock rule intact. Findings are ranked recommendations, each with minutes saved and the coverage it gives up. `timing` also reports `projection_fit` (fleet-config#1026): per test, which ones pay for a second browser projection without any engine or viewport signal, the audit half of `/e2e`'s rule that a second projection runs only for layout, touch targets, nav, composer and safe-area. **Waits before merges** (fleet-config#1134, from two real slimming lanes where removing waits saved about three times what merging nodes did): `scan` lists every clock wait in the test tree (`waits`: fixed sleeps, page timers, poll constants, timeouts of 10 s or more) and negative assertions whose needle appears nowhere else in the repo (`vacuous_candidates`: a check that can never fail); `timing` ranks the same waits by the measured seconds of the tests that pay them, counts only executed nodes (skipped ones apart), prefers the latest full-tier run over a later slice or backend-only run, names the first node (it carries the session boot), and counts page loads reached through a helper or fixture. `routing` names the rule that wins once a shadowed path's first rule stops matching, and prints the classifier command that checks each path. The judgment layer ranks waits before folds, prices every fold in executed nodes and seconds separately (parametrizing saves functions, not nodes; a fold whose cases reload saves about 0 s), never ranks a routing change as time when the gate does not consume the classifier, and asks every finding that moves or rewrites an assertion for a mutation proof. `/e2e-audit local <repo>` is a dry run that files nothing and leaves the growth baseline alone.
