# `/e2e`

- **`/e2e`** — the fleet's one owner of **e2e decisioning, execution, and inline suite maintenance** (fleet-config#556), built to stop full Chromium+WebKit runs being the price of every diff without ever under-testing. Fronts project-scaffolding's diff-proportionate routing convention (`docs/e2e-routing.md`): probes the repo with the deterministic `skills/_lib/e2e_route.py` (classifier / `[e2e]` table / suite / web-surface facts), runs the repo's own `scripts/classify_e2e.py` and honors its tier (`skip`/`static`/`full`, plus `surface` where a repo declares `[[e2e.surface]]` — project-scaffolding#258; fail-safe to `full`) verbatim, rejecting as a classifier error any tier it does not recognise, a `surface` missing its name or targets, or a key printed twice (fleet-config#902), **self-heals adoption** where the router is missing (byte-verbatim classifier copy from the scaffold + a conservative starter `[e2e]` table + the anti-drift test, all riding the current feature branch), and falls back to same-vocabulary LLM judgment only where no classifier can exist yet — uncertainty always escalates to `full`, never narrows. The same run maintains the suite as a side effect: tests deleted with the feature that used them, qualifying Loop-2 regressions added directly (respecting the <15-test target), routing-table rules kept honest. Delegated to by `/issue-finish` (step 3c), `/issue-yolo` (Phase 3d), and `/issue-batch` sub-agents — evaluation is mandatory before every PR, execution proportionate — and invocable standalone (`/e2e`, `/e2e plan`, `/e2e full`) mid-session after ad-hoc changes. A repo with no suite at all gets a worth-it evaluation (webapp/Streamlit repos only) rather than a silent pass. Every run with a suite also reports its size and gate time against the `[e2e] test_budget` / `time_budget_s` ratchets and its growth since the last audit, and hands the suite to `/e2e-audit` when any of them fires (fleet-config#901, #1018). **A second browser projection runs only where the engine or viewport matters** (layout, touch targets, nav, composer, safe-area); functional tests run on one engine (fleet-config#1026: 0 WebKit-engine product bugs in 400 app-launcher PRs, WebKit 61% of browser time, and iOS-only bugs need the device anyway). **Gate contract** (fleet-config#1134): `e2e_route.py probe` also prints `GATE_ROUTING=ok|broken|latent|not-consumed|unknown|n/a`: whether the repo's own gate scripts run the classifier and split its space-joined `E2E_PYTEST_TARGET` before pytest. A gate that passed the targets as one argument failed every branch touching two e2e modules (home-automation#784), and a gate that never runs the classifier makes `[e2e]` table edits save the gate nothing. `/e2e-audit`'s `routing` carries the same verdict, and `/propagate-vendored classify_e2e` reports it per adopter.
