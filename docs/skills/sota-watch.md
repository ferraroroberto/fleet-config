# `/sota-watch`

- **`/sota-watch`** — the **market lens**: a recurring state-of-the-art watch that notices when the *next* evaluation spike is due, since a one-off spike (token reduction #219, model tiers, the MCP surface audit #128) reaches its verdict and then goes silent while the market keeps moving. It walks a curated `watchlist.toml` (`.claude/skills/sota-watch/`) — per area: the adopted choice, the recorded verdict + date, the **disqualifiers** a challenger would have to clear, and a per-area `check_every_days` cadence — re-researches only the areas whose interval has elapsed (the `deep-research` harness per due area, sequential, polled to completion in-turn per fleet-config#314; bounded inline WebSearch as fallback), and reports **only changes**: one line for "no change", a short evidenced block when a challenger appears to clear the recorded disqualifiers. The `local-model-frontier` area is **delegated**, not researched — `local-llm-hub`'s own bi-weekly `/frontier-refresh` ledger (local-llm-hub#272) owns it, and this skill just relays its latest verdict table and flags staleness if that cadence slips. Run state (`last_checked` per area) lives in `~/.claude/sota-watch/state.json` — outside the repo, so the unattended run never commits; the digest accumulates as comments on the audit-managed `sota-watch ledger` issue (`kind=sota-watch` via `skills/_lib/audit_issue.py`, labelled `audit-meta`) with a Telegram ping. **Advisory, never auto-adopting**: a challenger becomes a drafted spike-issue outline in the digest, filed by a human — the #219 pattern (measure, trust-gate, verdict) stays the adoption gate, and watchlist verdicts change only via a reviewed PR after a spike concludes. Built to run unattended on a weekly app-launcher job. Built in #393.
