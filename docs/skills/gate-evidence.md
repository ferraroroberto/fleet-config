# Gate evidence (a green bound to the tree it ran against)

`skills/_lib/gate_evidence.py` replaces "green this session" (a remembered pass) with a pass bound to a content hash of the whole working tree. `run --label <L> -- <argv>` runs the gate itself (so the exit code is observed, not reported), hashes the tree before and after, and records `{cmd, exit, wtree, utc}` only when the two agree; a tree that changed mid-run, or an unhashable one, drops any earlier record for the label instead of leaving a stale pass. `check --label <L> [--expect-cmd]` prints exactly one of `FRESH` / `STALE` (changed paths named on stderr) / `MISSING` / `UNKNOWN`. The hash copies the index (`rev-parse --git-path index`, so linked worktrees work) to a temp file, points `GIT_INDEX_FILE` at it, and runs `git add -A` + `git write-tree`: the real index is never touched, committing identical content stays `FRESH`, any edit or new untracked non-ignored file goes `STALE`, ignored files (`.env`, `.venv`) never count. Evidence lives at `rev-parse --git-path gate-evidence.json`, outside the working tree and per worktree. `GIT_INDEX_FILE` has no `-c` form, so `git_run.run_git` gained a keyword-only `extra_env` that layers under `git_env()` — `GIT_OPTIONAL_LOCKS=0` cannot be dropped. Consumers: `/issue-finish` step 3 runs the gate through `run --label gate`; step 3c's no-double-run, step 5's skip-the-CI-wait and `/e2e`'s dedupe rule each ask `check`, and `/e2e` records its slice as `e2e-<tier>`. Anything but `FRESH` means re-run once or watch CI — it fails closed. Tested end to end against temp repos and a linked worktree (`tests/e2e/test_gate_evidence.py`).
