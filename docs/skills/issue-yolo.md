# `/issue-yolo`

- **`/issue-yolo <N | idea>`** — the issue workflow end to end in one unbroken run: `/issue-add` (skipped when given an existing issue number) → `/issue-start now` → build → **validate hard** → `/issue-finish`, with no approval pause in between. YOLO removes the plan-approval gate, never safety: the validation phase (the repo gate, the `/e2e` evaluation and an independent fresh-agent review) is the only thing between the idea and a merge, and any failure there stops the run before push. It takes a `--brief <path>` dispatch brief under the same rules as `/issue-start`. Use it when the approach is already settled and one validation pass covers the change; architectural or cross-cutting work goes through `/issue-start … plan`, and work whose blast radius reaches past the local repo, its CI and its tray is out of scope. The three-lane boundary with `/quick` and `/issue-start plan` is in [`/quick`](quick.md).
