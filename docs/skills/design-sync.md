# `/design-sync`

- **`/design-sync`** — the **web-app design-conformance** detector. Reads the fleet design system (`~/.claude/design.md` light + `~/.claude/design.dark.md` dark — Google's `design.md` schema, Vercel's two-file light/dark convention, GitHub-mobile palette), maps its tokens onto a target app's CSS custom properties (light + dark), and surfaces the values that have **drifted** from the spec — plus the spec's component and interaction contracts: the navigation contract (the floating bottom-tab pill), PWA install icons from the canonical `brand_gen` family with distinct regular/maskable assets, collapsible cards against the `disclosure` contract (card padding zeroed, summary height/padding, open-state divider, body padding), and the mobile contracts promoted from the home-automation app: editor `<dialog>`s (with or without a `<form>` wrapper) held to the `modal` contract, effective 44px hit-target authoring, Chart.js tick budgets + non-colour series cues, and the `loading/ready/empty/stale/error` async-lifecycle vocabulary. Rendered-only geometry (effective rects, overlap, the viewport×theme matrix) is reported as `unmeasured` unless the repo ships the canonical browser harness. It files exactly one deduped `design-drift` issue per repo through the *same* `skills/_lib/audit_issue.py` upsert machinery as `/codebase-audit`, so `design-drift` is a first-class audit bucket: `/cleanup-fleet design-drift` fans out fixers and `/issue-triage` treats it like any other. Default mode is read-only on code (reports + files the issue); `/design-sync apply` writes the aligned token values into the working tree for review. Skips Streamlit POC spikes and never re-authors nav/components (those are vendored verbatim from `project-scaffolding`). The fleet-wide weekly sweep that runs it across every web app is `/design-sweep` (below), with the `design-drift` bucket surfaced in the `/audit-fleet` digest.
  - **Tailnet-cert conformance** rides the same read as one adjacent infra check on the same web-app population: a Tailscale-reachable app (a `*.ts.net`/Tailscale mention in `README.md`/`CLAUDE.md`/`docs/**`) that still provisions HTTPS *only* via a self-signed CA + `/install-ca` mobileconfig dance, with no `tailscale cert` provisioner, is convention drift from the fleet standard of provisioning HTTPS with `tailscale cert`. The heuristic is a deterministic truth table in the pure, unit-tested `skills/_lib/cert_drift.py` (`detect`); on drift it files a **separate** deduped `cert-drift` issue (its own first-class bucket, never folded into `design-drift`) pointing at the standard, so `/cleanup-fleet cert-drift` can migrate them later. It never auto-applies the cert migration (`apply` only touches CSS), and a genuinely LAN-only app — self-signed but no Tailscale signal — correctly stays clean.
