# `/audit-fleet`

- **`/audit-fleet`** — scatter-gather wrapper that runs `/codebase-audit` across every `ferraroroberto` repo under `E:\automation\`. A single Python sweep (`skills/_lib/fleet_audit_scan.py`, `--dry-run`-able on demand) enumerates the fleet, syncs each repo, and gates every one of them in one pass — skipping the unchanged, auto-advancing the ledger for repos whose only commits since the last audit are `/cleanup-fleet` fixing their own findings, and batching low-significance organic change until it crosses the weighted-LOC threshold (`below_threshold` bucket) — handing the orchestrator a ready-made to-audit list. It then audits the genuinely-changed ones through a bounded concurrency window per the fleet's model-tier policy ([`docs/model-tiers.md`](../model-tiers.md)) — audit work runs at `hard` tier, with the ≤3-wide window enforcing the tier's Opus concurrency cap — and emits one diff-based weekly digest, genuinely-new findings called out separately from standing backlog (GitHub comment on the digest-state issue + Telegram ping + stdout). Alongside the rot it files, it runs a **second lens on the same read** — a *fleet practices ledger*: each sub-agent surfaces hard-won reusable solutions and generalizable-convention candidates (the inverse of a finding — an asset to remember, not rot to fix), merged into one living catalog issue in `project-scaffolding` so the best of each repo is discoverable fleet-wide. **Self-paces against the live session budget** ([`docs/rate-gate.md`](../rate-gate.md)): `statusline-command.ps1` caches the live 5h usage % to `~/.claude/hooks/state/rate-limits.json` on every render, so this skill reads it and pauses dispatch proactively, waiting in place until the window resets and resuming in the same run. A scheduled run with no fresh reading pauses and re-reads rather than dispatching blind. A bounded 3-pause safety net stops the wait rather than looping forever; anything left over is picked up by next week's idempotent ledger gate. Built to run unattended on a weekly app-launcher job.

  - **Dead-code line.** Each audited repo's sub-agent report carries the `Dead-code:` line from `/codebase-audit` step 10 (`dead-code leads: H hits, C confirmed`, or `not confirmed (<reason>)`), and the digest prints it beside that repo's result. It is not a ledger snapshot column.
  - **Structure baseline.** The same sweep reports, per repo, the size of `.structure-ratchet-baseline.json` read from `origin/<default>` (never the checkout): baselined files, functions and directories, plus the lines over the limits, each with its change since the previous digest, and a fleet total with the three largest repos. A repo without the file is `not adopted` and one whose file cannot be read is `unknown`; neither counts as zero. A repo whose counts or excess rose against a previous reading puts `structure debt grew` in the digest headline; a shrunk baseline is not flagged. The numbers are stored in the digest-state issue under `structure:<repo>:` keys (`skills/_lib/structure_debt/`).
  - **Gate coverage.** The same sweep reports, per repo, how much the ratchets already enforce, read from `origin/<default>`: the enabled ratchet tables in `.fleet.toml`, the `[conventions_ratchet]` rules, and the baselined hit count per ratchet, each with its change since the previous digest, plus the fleet total. A repo with no enabled ratchet table is `not adopted` and an unreadable `.fleet.toml` or baseline is `unknown`; neither counts as zero. The numbers are stored under `gate:<repo>:` keys (`skills/_lib/gate_coverage/`). Nothing here is counted by an auditor.
