# `/context-purge`

- **`/context-purge`** — the compression counterpart to `/context-audit`: rewrite the fleet's markdown context files (`global-CLAUDE.md`, project `CLAUDE.md`s, `SKILL.md`s) with a senior-editor eye, cutting prose while preserving **every directive, gotcha, and trigger** — enforced by a directive-inventory contract, the deterministic `check.py` (marked machine-managed blocks byte-identical, quoted trigger phrases verbatim; unit-tested via the acceptance matrix), an `audit.py` before/after, and a Haiku-agent before/after comprehension probe (compressed file must score ≥ the original). Default mode purges the fleet-config-owned surface on a branch and opens a PR with the validation report; `fleet` mode adds every sister repo's `CLAUDE.md` + `.claude/skills/*/SKILL.md`, one branch/PR per repo. **The run merges its own validated rewrites:** `digest.py merge-check` is the deterministic go/no-go (`check.py`/`audit.py`/repo gate confirmed, directive inventory fully discharged, no probe regression, nothing unrecorded), `validate` re-applies it to every repo recorded as merged, and a rewrite that fails it is never merged and re-enters `to_purge` next run. Each merged primary checkout is fast-forwarded through `untrack_guard.py` only when clean, on its default branch and session-free, otherwise reported as left; fleet-config's own PR clears the same bar and merges last. The owner reviews afterwards from the digest and reverts with one `git revert`. A **skip-unchanged ledger** (`gate.py`, content hashes in the `context-purge ledger` issue) means a file is re-assessed only when its bytes changed since last assessed — an unchanged week costs one `gh` read and stops. Every run then publishes a **per-run digest** (`digest.py`) rendered from the run's own structured data rather than from the PR bodies: headline figures, a **What changed** section (per file token and line delta, blast radius — which agents and sessions load it — and per repo the merged PR/SHA, its `git revert`, and whether the live checkout was fast-forwarded), probe coverage **per file** (a repo that probed its `CLAUDE.md` and skipped four `SKILL.md`s is not "probed"), every rewritten skill `description:` with before/after word counts, repos ranked by what a lost directive would cost, and every reviewer decision, deliberate non-fix and assessed-but-untouched file. It lands as a comment on the `[ledger] context-purge run digests` issue plus a short Telegram ping via the shared `notify_send.py`; an unrecorded figure renders as *not recorded*, never as `0`. Delivery is **asserted, not assumed** — `delivery_check.py` (via `claude_progress.py --delivery-check`) fails the scheduled job unless a fresh digest exists *and* reports `status=complete` *and* `delivery=posted`, so a partial run or a silently failed ping turns the job red instead of exiting 0. Runs unattended weekly (Saturdays 01:00, Opus, `run-weekly.bat` → app-launcher Job). Fleet-only tier deliberately — a global skill description in every session would be self-defeating for a skill whose purpose is shrinking that surface.
